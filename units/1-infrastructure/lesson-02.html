Lesson 1.2: Docker Compose from Zero

BABY

📚 What You Are Learning

One concept: How to define and manage multi-container applications using docker-compose.yml files.

Instead of running docker run commands with 20 flags, you'll write one YAML file and bring up your entire stack with docker compose up -d.

✅ You Should Already Have

  • Docker installed and running (from Lesson 1.1)
  • docker ps works without errors
  • A text editor (VS Code, nano, vim, or Notepad++)

📖 New Words

  • Docker Compose — Tool for defining multi-container apps
  • YAML — Human-readable data format (indentation matters!)
  • Volume — Persistent storage for containers
  • Port — Network endpoint (e.g., 8080:80)

🔧 Lab Steps: Your First docker-compose.yml

Create a Project Directory

🪟 Windows
🐧 Linux

Open Ubuntu terminal (WSL2) and run:

mkdir -p ~/homelab/test-stack
cd ~/homelab/test-stack
mkdir -p ~/homelab/test-stack
cd ~/homelab/test-stack

Create docker-compose.yml

Create a new file called docker-compose.yml with this content:

version: "3.8"

services:
  whoami:
    image: traefik/whoami
    container_name: whoami-test
    ports:
      - "8080:80"
    restart: unless-stopped

What this does: Pulls the traefik/whoami image (a simple web server that shows request info) and exposes it on port 8080.

Start the Stack

docker compose up -d

The -d flag runs containers in detached mode (background).

You should see Docker pulling the image and starting the container.

Verify It's Running

docker compose ps

You should see the whoami-test container with status "running".

Also check with plain Docker:

docker ps

Test the Web Interface

Open a web browser and navigate to:

🪟 Windows
🐧 Linux

Open: http://localhost:8080

If on a headless server, find your server's IP and open: http://SERVER-IP:8080

Or use curl from terminal: curl http://localhost:8080

You should see output showing hostname, IP, headers, etc.

Check Logs

docker compose logs whoami

You'll see the HTTP requests you just made.

Live log following: docker compose logs -f whoami (Ctrl+C to stop)

Stop the Stack

docker compose down

This stops and removes the container (but keeps the image for next time).

Bring It Back Up

docker compose up -d

Notice how fast it starts the second time? The image is already downloaded.

📚 Understanding docker-compose.yml Structure

Basic Anatomy:

version: "3.8"               # Compose file format version

services:                    # Define your containers here
  service-name:              # Give it a name
    image: repo/imagename    # Which image to use
    container_name: my-app   # Optional custom container name
    ports:                   # Expose ports to host
      - "8080:80"            # host:container
    volumes:                 # Mount storage
      - ./config:/config     # host:container
    environment:             # Set environment variables
      - PUID=1000
      - PGID=1000
    restart: unless-stopped  # Restart policy

Key Fields Explained:

  • image: Docker Hub image name (e.g., linuxserver/sonarr:latest)
  • ports: Format is "HOST_PORT:CONTAINER_PORT"
  • volumes: Maps host paths to container paths for persistent data
  • environment: Variables the container needs (UID/GID, API keys, etc.)
  • restart: unless-stopped means start on boot, stay running

🧪 Practice Exercise: Add a Second Service

Edit your docker-compose.yml to add a second container:

version: "3.8"

services:
  whoami:
    image: traefik/whoami
    container_name: whoami-test
    ports:
      - "8080:80"
    restart: unless-stopped

  nginx:
    image: nginx:alpine
    container_name: nginx-test
    ports:
      - "8081:80"
    restart: unless-stopped

Run docker compose up -d again. Docker Compose will:

  • Leave the whoami container running (no changes)
  • Start the new nginx container

Now you can access:

  • http://localhost:8080 → whoami
  • http://localhost:8081 → nginx welcome page

🔧 Troubleshooting Decision Tree

Problem: "docker compose: command not found" or "docker-compose: command not found"

→ Modern Docker uses docker compose (space, not hyphen)
→ Check Docker version: docker --version (need 20.10+)
→ On older systems, install docker-compose-plugin: sudo apt install docker-compose-plugin

Problem: "port is already allocated"

→ Another container or process is using that port
→ Find what's using it: sudo lsof -i :8080 (Linux) or netstat -ano | findstr :8080 (Windows)
→ Change the port in your compose file: "8082:80" instead of "8080:80"

Problem: "ERROR: yaml.parser.ParserError"

→ YAML is indentation-sensitive! Use 2 spaces (not tabs)
→ Check for missing colons or incorrect alignment
→ Use a YAML validator: yamllint.com

Problem: Container starts but immediately stops

→ Check logs: docker compose logs SERVICE-NAME
→ Look for error messages about missing env vars or config files
→ Some containers need volumes or environment variables to run
